1. HIGH-LEVEL PROJECT OVERVIEW & ARCHITECTURE
===============================================================================
CIVICLY is a single-page civic issue reporting website. 
It allows citizens to:
  - View civic issue categories (Roads, Electricity, Sanitation, Water & Drainage).
  - Filter community incident reports by category dynamically using JavaScript.
  - Submit a new civic report using a validated HTML form.
  - Receive an instant ticket confirmation number (e.g. CIV-1042) generated by JS.

Architecture:
  - Frontend: HTML5 + CSS3 + Bootstrap 5 + Vanilla JavaScript (Fetch API).
  - Backend: Node.js + Express.js (REST API following course cheatsheet).
  - Database: MongoDB + Mongoose ODM (Civicly Issue collection).
  - Staff Dashboard: Minimal staff operations page for reviewing and updating issue statuses.
  - All images are stored locally in the "images/" folder.
  - Strict compliance with syllabus documents & syntax cheat sheet.

2. HTML5 BREAKDOWN (index.html)
===============================================================================
HTML (HyperText Markup Language) provides the STRUCTURE of the website.

Key HTML Tags Used & Their Purpose:

1. <!DOCTYPE html>
   - Tells the browser that this document is written in modern HTML5.

2. <html lang="en"> ... </html>
   - The root element enclosing all content on the page. Language is English.

3. <head> ... </head>
   - Contains metadata (character set, viewport settings), title, and stylesheet links.
   - <meta charset="UTF-8">: Supports all standard text characters.
   - <meta name="viewport" content="width=device-width, initial-scale=1.0">:
     Ensures proper scaling on mobile phones and mobile devices.
   - <title>: Sets the text displayed on the browser tab ("CIVICLY").
   - <link rel="stylesheet">: Connects Bootstrap 5 and custom style.css files.

4. <body> ... </body>
   - Contains all visible content displayed to the user.

5. <nav> ... </nav>
   - Semantic HTML tag used to define the top navigation bar.

6. <section> ... </section>
   - Used to divide the webpage into distinct content areas:
     #home (Hero), #categories (Categories), #issues (Queue), #report (Form), #about (About).

7. Headings (<h1>, <h2>, <h5>, <h6>):
   - <h1>: Main Hero title ("Your City. Your Voice."). Used once for primary heading.
   - <h2>: Section headings ("What can you report?", "Issues Around You").
   - <h5> / <h6>: Sub-headings for cards and small module titles.

8. <p> (Paragraph):
   - Displays body text, explanations, and descriptions.

9. <div> (Division):
   - Block-level container used to group elements together for styling and layout grids.

10. <span> (Inline Container):
    - Used to style specific inline text or display small status badges (e.g., "In Progress").

11. <img> (Image):
    - Embeds photos into the page. 
    - src attribute: Points to the local file path (e.g., src="images/roads.jpg").
    - alt attribute: Provides alternative text if the image fails to load.

12. <a> (Anchor / Link):
    - Creates hyperlinks. Used in navbar and buttons (e.g., href="#report" scrolls to the form).

13. <button>:
    - Interactive button elements triggered by user clicks (e.g., Category filter buttons).

14. Form Tags (<form>, <input>, <select>, <option>, <textarea>):
    - <form id="civicReportForm" onsubmit="...">: Groups inputs together for submission.
    - <input type="text">: Text box for Name, Issue Title, Location.
    - <select> / <option>: Dropdown menu to choose a Category.
    - <textarea>: Multi-line text box for detailed problem description.
    - <input type="file">: Allows users to pick an evidence photo from their computer.

15. <footer> ... </footer>
    - Semantic tag for the bottom copyright bar ("CIVICLY © 2026").

   - Border-Radius: Rounds card corners (e.g., border-radius: 12px).

     .category-card { transition: transform 0.3s ease, box-shadow 0.3s ease; }

5. JAVASCRIPT BREAKDOWN (script.js)
===============================================================================
JavaScript adds INTERACTIVITY and DYNAMIC LOGIC to the static HTML page.

Key Concepts Demonstrated in script.js:

-------------------------------------------------------------------------------
Concept A: Category Filtering Logic (filterIssues)
-------------------------------------------------------------------------------
Function Signature:
  function filterIssues(category, buttonElement)

How it Works (Line-by-Line):
1. DOM Selection:
   const issueCards = document.getElementsByClassName("issue-card-wrapper");
   - Gets an array-like list of all issue card elements on the page.

2. Loop Iteration (For Loop):
   for (let i = 0; i < issueCards.length; i++) { ... }
   - Iterates through every issue card one by one.

3. Getting Data Attributes:
   const cardCategory = card.getAttribute("data-category");
   - Reads the category stored in the HTML tag (e.g., data-category="Roads").

4. Conditional Display (if / else):
   if (category === "All" || cardCategory === category) {
     card.style.display = "block"; // Show card
   } else {
     card.style.display = "none";  // Hide card
   }

5. Updating Button Active Styles:
   - Uses querySelectorAll(".btn-filter") and forEach to remove the 'active' class 
     from all filter buttons, then adds 'active' to the clicked button.

-------------------------------------------------------------------------------
Concept B: Form Validation & Ticket Generation (validateReportForm)
-------------------------------------------------------------------------------
Function Signature:
  function validateReportForm(event)

How it Works (Line-by-Line):
1. Event Prevention:
   event.preventDefault();
   - Prevents the browser from reloading the page when the form is submitted.

2. Reading Form Input Values:
   const fullName = document.getElementById("reporterName").value.trim();
   const issueTitle = document.getElementById("issueTitle").value.trim();
   const category = document.getElementById("issueCategory").value;
   // Structured Location Inputs (Resolving City Name Ambiguity e.g. Srinagar):
   const city = document.getElementById("locCity").value.trim();
   const area = document.getElementById("locArea").value.trim();
   const ward = document.getElementById("locWard").value.trim();
   const landmark = document.getElementById("locLandmark").value.trim();
   const description = document.getElementById("issueDescription").value.trim();
   - Uses .value to read what the user typed, and .trim() to remove extra spaces.

3. PIN Code & Location Disambiguation for Duplicate Issue Grouping:
   - Required Fields:
     1. Six-digit PIN Code (Validated using basic JS: length === 6 && !isNaN(pinCode))
     2. Area / Locality (Required)
     3. Nearby Landmark / Spot (Required)
     4. Issue Category (Required)
     5. Issue Title & Description
   - Basic Prototype Duplicate Detection:
     - Algorithm: Iterates through issues and compares normalized PIN code, locality, landmark, and category:
       normalizeText(a.pinCode) === normalizeText(b.pinCode) &&
       normalizeText(a.locality) === normalizeText(b.locality) &&
       normalizeText(a.landmark) === normalizeText(b.landmark) &&
       normalizeText(a.category) === normalizeText(b.category)
     - Labeling: If matching reports are detected, they are flagged with:
       "⚠️ Possible duplicate — verify location"
     - Educational Note for Viva: This is a basic prototype demonstration and NOT a production-grade duplicate detection engine (which would require geospatial clustering, NLP text similarity, or street map APIs). It strictly adheres to course-level JavaScript.

4. Validation Checks (If Statements):
   if (fullName === "") { showError("Please enter your full name."); return false; }
   if (issueTitle === "") { showError("Please enter the issue title."); return false; }
   if (category === "") { showError("Please select an issue category."); return false; }
   if (pinCode.length !== 6 || isNaN(pinCode) || pinCode.indexOf(" ") !== -1) {
     showError("Please enter a valid 6-digit postal PIN code.");
     return false;
   }
   if (area === "") { showError("Please enter the Area / Locality."); return false; }
   if (landmark === "") { showError("Please enter a nearby Landmark or spot."); return false; }
   if (description === "") { showError("Please provide a description."); return false; }
   if (category === "") { showError("Please select an issue category."); return false; }
   if (city === "") { showError("Please enter the City / Town."); return false; }
   if (area === "") { showError("Please enter the Area / Locality."); return false; }
   if (landmark === "") { showError("Please enter a nearby Landmark."); return false; }
   if (description === "") { showError("Please provide a description."); return false; }

4. Generating a Unique Ticket Number:
   const randomNum = Math.floor(1000 + Math.random() * 9000);
   const ticketId = "CIV-" + randomNum;
   - Generates a 4-digit random number (e.g., 1042) to form a ticket ID like "CIV-1042".

5. DOM Manipulation to Display Success Card:
   ticketDisplay.style.display = "block";

     <div class="ticket-card p-4 text-center">

6. STEP-BY-STEP WEBSITE FLOW
===============================================================================
What happens when a user uses the website:

1. User Opens index.html:
   - Browser reads HTML structure, loads Bootstrap 5 CSS & style.css.
   - Renders top dark navigation bar and Hero section with background image.

2. User Scrolls to Categories:
   - Sees 4 structured category cards (Roads, Electricity, Sanitation, Water).

3. User Clicks a Filter Button (e.g., "Roads"):
   - HTML triggers onclick="filterIssues('Roads', this)".
   - JS loops through all cards. Cards with data-category="Roads" remain visible;
     other cards get hidden (style.display = 'none').

4. User Fills the Report Form & Clicks Submit:
   - Form triggers onsubmit="return validateReportForm(event)".
   - JS prevents page refresh and checks if inputs are empty.
   - If empty: Shows a red error alert box using DOM manipulation.
   - If valid: Generates ticket ID (e.g., CIV-4821), builds a green ticket box 
     using innerHTML, resets form inputs, and scrolls down to show the ticket.

7. FREQUENTLY ASKED VIVA QUESTIONS & ANSWERS
===============================================================================

Q1: What is CIVICLY?
A1: CIVICLY is a static Single Page Web Application prototype for reporting and tracking urban civic hazards like potholes, streetlights, garbage overflow, and water leaks.

Q2: What technologies did you use?
A2: We used standard FSDL syllabus technologies: HTML5 for page structure, CSS3 and Bootstrap 5 for responsive design, and Vanilla JavaScript for filtering and form validation.

Q3: Is there a database or backend server connected?
A3: No, sir/ma'am. This is a pure client-side frontend project. Data validation and ticket generation (e.g., CIV-1042) are handled dynamically using JavaScript DOM manipulation without a server.

Q4: How does your category filtering work in JavaScript?
A4: We attach an onclick event handler to filter buttons that calls filterIssues(category). It selects all issue card elements using getElementsByClassName, loops through them, compares their data-category attribute, and sets style.display to 'block' or 'none'.

Q5: How do you handle form validation?
A5: In script.js, validateReportForm(event) uses event.preventDefault() to stop page reload. It retrieves input values using document.getElementById().value.trim() and checks if any required fields are empty. If validation fails, an error message is displayed; if it passes, a ticket confirmation card is generated using innerHTML.

Q6: Where are your images stored?
A6: All images are stored locally inside the project's "images/" folder (e.g., images/roads.jpg, images/hero.jpg) so the site loads completely offline.
